# 개발 근거 문서

이 디렉터리의 문서 중 `main`에 병합된 버전만 개발 근거로 사용합니다. 문서 변경은 PR로 제안하고, 리더가 승인해 병합합니다. 아래 규칙은 PR과 병합 커밋마다 자동 검사로 확인합니다.

## 근거 문서 목록

| 문서 | 담는 내용 |
| --- | --- |
| `docs/requirements.md` | 배경, 요구사항(REQ), API 계약, 범위 밖 |
| `docs/design.md` | 구조, API, UI, 수용 기준, 위험 |

첫 기능 요청에서 두 문서를 만들고, 이후 요청은 필요한 절만 고칩니다.

## 문서 규칙

1. `docs/requirements.md`에는 `## 배경`, `## 요구사항`, `## API 계약`, `## 범위 밖` 절이 있고 내용이 비어 있지 않아야 합니다.
2. 요구사항은 `## 요구사항` 절에 한 줄씩 `- **REQ-01** 내용` 형식으로 적습니다.
   - ID는 `REQ-` 뒤에 두 자리 이상의 숫자이며 중복되지 않습니다. 한 번 쓴 ID는 다른 의미로 다시 쓰지 않습니다.
   - 아직 구현하지 않은 요구사항은 ID 바로 뒤에 `(구현 예정 #이슈번호)`를 붙입니다. 구현을 맡을 이슈가 아직 없으면 `(구현 예정)`만 붙입니다.
     - 예: `- **REQ-07** (구현 예정 #12) 마감일이 지난 항목을 구분해 표시한다.`
3. `docs/design.md`에는 `## 구조`, `## API`, `## UI`, `## 수용 기준`, `## 위험` 절이 있고 내용이 비어 있지 않아야 합니다.
4. 정의한 모든 요구사항 ID는 `## 수용 기준`에서 한 번 이상 참조하며, 정의하지 않은 ID를 참조하지 않습니다.
5. 테스트와의 연결:
   - 구현된 요구사항(구현 예정 표시가 없는 요구사항)마다 그 요구사항을 확인하는 Go 테스트가 하나 이상 있어야 합니다.
   - 테스트는 테스트 함수 바로 위 주석에 요구사항 ID를 적어 연결합니다. 한 테스트가 여러 요구사항을 확인할 수 있습니다.

     ```go
     // REQ-03, REQ-04: 빈 제목은 400으로 거절하고 목록을 바꾸지 않는다.
     func TestCreateRejectsBlankTitle(t *testing.T) { ... }
     ```

   - 구현 예정 요구사항을 참조하는 테스트는 둘 수 없습니다. 테스트를 추가하는 PR에서 해당 요구사항의 구현 예정 표시를 지웁니다.
6. `VERSION` 파일이 있으면 `0.1.0` 같은 `주.부.수` 형식이어야 하고, `CHANGELOG.md`에 `## [0.1.0] - YYYY-MM-DD` 형식의 해당 버전 절이 있어야 합니다.

## 구현 검사

구현 PR과 병합 커밋은 위 문서 규칙에 더해 다음을 통과해야 합니다.

- `go build ./...`가 성공합니다.
- `go test ./...`의 모든 테스트가 통과하고, 실행된 테스트가 한 건 이상이며, 건너뛴 테스트가 없습니다.
- 구현된 요구사항마다, 그 요구사항을 참조하는 테스트가 실제로 실행되어 통과합니다.

## 프로젝트 제약

- Go 표준 라이브러리와 HTML/CSS/JavaScript만 사용합니다. 외부 모듈과 CDN을 쓰지 않습니다.
- 저장소 루트의 단일 모듈(`go.mod`의 `module todo`)로 둡니다. 서버는 `go run .`으로 실행하며 `-listen` 플래그(기본값 `127.0.0.1:8091`)를 받습니다.
- 화면은 `index.html` 한 파일로 만들고 서버가 `/`에서 제공합니다. API는 `/api/` 아래 JSON으로 제공합니다.
- 데이터는 서버 메모리에 보관합니다. 테스트는 `net/http/httptest`로 작성하고 네트워크나 외부 프로세스 없이 실행되어야 합니다.
- 구현 PR은 `docs/` 아래에서 구현 예정 표시를 지우는 변경만 할 수 있습니다. 동작 정의를 바꿔야 하면 문서 PR로 따로 제안합니다.
- 버그 수정은 먼저 버그를 재현하는 실패 테스트를 커밋하고, 그다음 수정 커밋을 올립니다. 재현 테스트의 주석에는 관련 요구사항 ID와 버그 이슈 번호(예: `#15`)를 적습니다.
- 파일을 삭제하거나 이름을 바꾸지 않습니다. 필요하면 PR 설명에 이유를 적고 리더에게 맡깁니다.
