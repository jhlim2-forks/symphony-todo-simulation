# 요구사항

## 배경

팀원이 브라우저에서 할 일을 간단히 적고 지울 수 있는 웹앱이 필요합니다(이슈 #4). 첫 버전은 할 일 추가, 추가한 순서대로 목록 보기, 완료 표시와 해제, 개별 삭제까지만 제공합니다.

화면은 한 페이지이고 한국어로 보여 줍니다. 데이터는 서버 메모리에만 두므로 서버를 다시 켜면 목록이 비어 있어도 괜찮습니다. 로그인과 여러 사용자, 데이터베이스는 이번 범위가 아닙니다.

목록을 "진행 중 / 완료"로 나눠 보는 필터는 나중에 만들기로 하고, 이번에는 정의만 남겨 둡니다. 리더 결정에 따라 화면에는 필터가 들어갈 자리만 설계로 정해 두고 동작은 만들지 않습니다.

## 요구사항

- **REQ-01** (구현 예정 #4) 사용자가 할 일 제목을 입력해 새 할 일을 추가할 수 있다. 추가된 할 일은 고유한 숫자 ID를 가지고, 처음에는 완료되지 않은 상태다.
- **REQ-02** (구현 예정 #4) 제목의 앞뒤 공백은 제거한 뒤 저장한다. 공백을 제거한 제목이 비어 있으면 추가를 거절하고 목록을 바꾸지 않는다.
- **REQ-03** (구현 예정 #4) 공백을 제거한 제목이 200자(문자 수 기준)를 넘으면 추가를 거절하고 목록을 바꾸지 않는다. 200자까지는 허용한다.
- **REQ-04** (구현 예정 #4) 할 일 목록은 추가한 순서(오래된 것이 위)대로 보여 준다. 완료 표시나 해제는 순서를 바꾸지 않는다.
- **REQ-05** (구현 예정 #4) 목록의 할 일을 완료로 표시할 수 있고, 완료된 할 일을 다시 미완료로 해제할 수 있다. 같은 상태로 다시 바꿔도 오류 없이 그 상태를 유지한다.
- **REQ-06** (구현 예정 #4) 목록의 할 일을 하나씩 삭제할 수 있다. 삭제한 할 일은 목록에서 사라지고 다른 할 일의 순서와 상태는 그대로 유지된다.
- **REQ-07** (구현 예정 #4) 없는 ID로 상태 변경이나 삭제를 요청하면 해당 할 일이 없음을 알리고 목록을 바꾸지 않는다.
- **REQ-08** (구현 예정 #4) 화면은 한 페이지(`index.html`)이고 모든 안내 문구와 오류 메시지를 한국어로 보여 준다. 추가, 완료 표시와 해제, 삭제를 이 한 페이지에서 모두 할 수 있다. 화면에 보여 주는 오류 문구는 API 계약에 정해 둔 한국어 문구이거나, 계약에 없는 응답일 때 쓰는 한국어 기본 문구 "요청을 처리할 수 없습니다. 잠시 후 다시 시도해 주세요."뿐이다. 응답 본문의 다른 내용은 화면에 그대로 보여 주지 않는다.
- **REQ-09** (구현 예정 #4) 할 일은 서버 메모리에만 보관한다. 서버를 다시 시작하면 목록은 빈 상태로 시작한다.
- **REQ-10** (구현 예정) 목록을 "전체 / 진행 중 / 완료"로 나눠 보는 필터를 제공한다. 이번 요청에서는 만들지 않고, 화면에 들어갈 자리만 설계에 정해 둔다.

## API 계약

- 모든 API는 `/api/` 아래에 두고 요청과 응답 본문은 JSON(`Content-Type: application/json; charset=utf-8`)을 사용한다.
- 할 일 한 건의 표현: `{"id": 1, "title": "장보기", "done": false}`
  - `id`: 1부터 시작해 추가할 때마다 커지는 정수. 삭제한 ID는 다시 쓰지 않는다.
  - `title`: 앞뒤 공백을 제거한 제목 문자열.
  - `done`: 완료 여부(`true`/`false`).
- 오류 응답 본문: `{"error": {"code": "<코드>", "message": "<한국어 안내>"}}`
  - `code`는 아래에 정의한 값만 사용하고, `message`는 그 코드에 정해 둔 한국어 문구를 글자 그대로 담는다.
  - 서버는 정의하지 않은 코드나 문구(내부 오류 문자열, 사용자가 보낸 값, 다른 언어의 문구 등)를 오류 응답에 담지 않는다.

| 메서드 | 경로 | 요청 본문 | 성공 응답 | 오류 |
| --- | --- | --- | --- | --- |
| `GET` | `/` | 없음 | `200` + `index.html` | - |
| `GET` | `/api/todos` | 없음 | `200` + `{"todos": [할 일, ...]}` (추가한 순서, 비어 있으면 `[]`) | - |
| `POST` | `/api/todos` | `{"title": "장보기"}` | `201` + 추가된 할 일 | `400 invalid_json`, `400 title_blank`, `400 title_too_long` |
| `PATCH` | `/api/todos/{id}` | `{"done": true}` | `200` + 변경된 할 일 | `400 invalid_json`, `400 done_required`, `404 not_found` |
| `DELETE` | `/api/todos/{id}` | 없음 | `204`(본문 없음) | `404 not_found` |

- 오류 코드와 안내 문구
  - `invalid_json`: "요청 형식이 올바르지 않습니다." (JSON이 아니거나 `title`이 문자열이 아닌 등)
  - `title_blank`: "할 일 제목을 입력해 주세요."
  - `title_too_long`: "할 일 제목은 200자까지 입력할 수 있습니다."
  - `done_required`: "완료 여부(done)를 true 또는 false로 보내 주세요."
  - `not_found`: "해당 할 일을 찾을 수 없습니다."
  - `method_not_allowed`: "허용되지 않은 요청 방식입니다."
- 경로의 `{id}`가 정수가 아니면 `404 not_found`로 응답한다.
- 위 표에 없는 경로는 `404 not_found`, 표에 있는 경로에 정의되지 않은 메서드는 `405 method_not_allowed`로 응답한다. 이 두 응답도 위의 오류 응답 본문 형식과 문구를 그대로 따른다.

## 범위 밖

- 로그인, 사용자 계정, 여러 사용자 구분, 권한.
- 데이터베이스와 파일 등 영속 저장. 서버 재시작 후 목록이 비는 것은 정상 동작이다(REQ-09).
- "진행 중 / 완료" 필터의 동작 구현. 이번에는 정의와 화면 자리만 두고 나중에 별도 이슈로 만든다(REQ-10).
- 아직 정하지 않아 이번에 다루지 않는 것: 추가한 할 일의 제목 수정, 여러 건 한 번에 삭제하거나 완료 처리, 완료된 항목 일괄 정리, 마감일·우선순위·정렬 변경, 검색, 목록 페이지 나누기, 되돌리기(삭제 취소), 삭제 전 확인 절차.
- 배포 환경 구성, 모바일 전용 화면, 접근성·디자인 시스템 적용, 다국어 지원.
