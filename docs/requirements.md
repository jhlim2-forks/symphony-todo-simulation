# 요구사항

## 배경

팀원이 브라우저에서 할 일을 간단히 적고 지울 수 있는 웹앱이 필요합니다(이슈 #4). 첫 버전은 할 일 추가, 추가한 순서대로 목록 보기, 완료 표시와 해제, 개별 삭제까지만 제공합니다.

화면은 한 페이지이고 한국어로 보여 줍니다. 데이터는 서버 메모리에만 두므로 서버를 다시 켜면 목록이 비어 있어도 괜찮습니다. 로그인과 여러 사용자, 데이터베이스는 이번 범위가 아닙니다.

목록을 나눠 보는 필터는 첫 버전에서는 만들지 않고 화면에 들어갈 자리만 설계에 정해 두었습니다. 그 자리에 들어갈 동작은 아래 이슈 #14 단락에서 정의하므로, 지금 이 문서가 정하는 동작은 "화면에 필터를 제공한다"입니다(REQ-10, REQ-15~REQ-17).

이어서 할 일마다 마감일을 붙이는 동작을 정의합니다(이슈 #7). 마감일은 날짜만 쓰고 시각과 시간대는 다루지 않습니다. 추가할 때 고르거나 비워 둘 수 있고, 나중에 바꾸거나 지울 수 있으며, 목록에 보이고, 실제로 없는 날짜(예: 2026-02-30)는 거절합니다. 마감일이 지난 항목을 눈에 띄게 하는 일은 요청에서 제외되어 별도 이슈로 둡니다. 우선순위 기능과 어느 것을 먼저 할지에 대해서는 리더가 마감일을 먼저 진행하기로 결정했으므로, 이번 문서 변경은 마감일만 정의하고 우선순위는 범위 밖에 남겨 둡니다.

마지막으로 "전체 / 진행 중 / 완료" 필터의 동작을 정의합니다(이슈 #14). 첫 버전에서는 화면에 자리만 비워 두었기 때문에, 어떤 선택지를 두는지·처음 어떤 선택이 켜져 있는지·어디에서 거르는지·걸러진 목록이 비었을 때 보여 줄 한국어 문구를 여기서 확정합니다. 리더 결정에 따라 처음 선택은 "전체"이고, 거르기는 화면(클라이언트)에서만 합니다. 서버는 필터 조건을 받지 않고 언제나 전체 목록을 돌려줍니다. 또한 리더 결정에 따라 할 일을 추가하거나 삭제한 뒤에도 고른 필터는 초기화하지 않고 그대로 유지합니다(REQ-17). 기본 기능(이슈 #4)이 끝난 뒤에 진행합니다. 화면을 새로 열어도 선택을 되살려 주는 것과 서버에서 거르는 방식은 이번에 정하지 않고 범위 밖에 둡니다.

## 요구사항

- **REQ-01** 사용자가 할 일 제목을 입력해 새 할 일을 추가할 수 있다. 추가된 할 일은 고유한 숫자 ID를 가지고, 처음에는 완료되지 않은 상태다.
- **REQ-02** 제목의 앞뒤 공백은 제거한 뒤 저장한다. 공백을 제거한 제목이 비어 있으면 추가를 거절하고 목록을 바꾸지 않는다.
- **REQ-03** 공백을 제거한 제목이 200자를 넘으면 추가를 거절하고 목록을 바꾸지 않는다. 200자까지는 허용한다. 글자 수는 바이트 수가 아니라 유니코드 문자(코드 포인트) 수로 세며, 한글 "가", 영문자 "a", 숫자, 이모지 "🙂"처럼 화면에 한 글자로 보이는 문자는 종류와 상관없이 각각 1자로 센다. 따라서 한글 200자 제목은 허용하고 한글 201자 제목은 거절한다. 단, 여러 문자를 이어 붙여 한 글자처럼 보이는 이모지(가족 이모지, 피부색을 붙인 이모지 등)는 이어 붙인 문자 수만큼 센다.
- **REQ-04** 할 일 목록은 추가한 순서(오래된 것이 위)대로 보여 준다. 완료 표시나 해제는 순서를 바꾸지 않는다.
- **REQ-05** 목록의 할 일을 완료로 표시할 수 있고, 완료된 할 일을 다시 미완료로 해제할 수 있다. 같은 상태로 다시 바꿔도 오류 없이 그 상태를 유지한다.
- **REQ-06** 목록의 할 일을 하나씩 삭제할 수 있다. 삭제한 할 일은 목록에서 사라지고 다른 할 일의 순서와 상태는 그대로 유지된다.
- **REQ-07** 없는 ID로 상태 변경이나 삭제를 요청하면 해당 할 일이 없음을 알리고 목록을 바꾸지 않는다.
- **REQ-08** 화면은 한 페이지(`index.html`)이고 모든 안내 문구와 오류 메시지를 한국어로 보여 준다. 추가, 완료 표시와 해제, 삭제를 이 한 페이지에서 모두 할 수 있다. 화면에 보여 주는 오류 문구는 API 계약에 정해 둔 한국어 문구이거나, 계약에 없는 응답일 때 쓰는 한국어 기본 문구 "요청을 처리할 수 없습니다. 잠시 후 다시 시도해 주세요."뿐이다. 응답 본문의 다른 내용은 화면에 그대로 보여 주지 않는다.
- **REQ-09** 할 일은 서버 메모리에만 보관한다. 서버를 다시 시작하면 목록은 빈 상태로 시작한다.
- **REQ-10** (구현 예정 #14) 목록을 "전체 / 진행 중 / 완료"로 나눠 보는 필터를 화면에 제공한다. 선택지는 이 세 가지뿐이고 한 번에 하나만 고를 수 있다. 화면에 처음 들어갔을 때는 "전체"가 선택되어 있다. "전체"는 모든 할 일, "진행 중"은 완료되지 않은 할 일(`done`이 `false`), "완료"는 완료된 할 일(`done`이 `true`)만 목록에 보여 준다. 필터 문구도 모두 한국어다.
- **REQ-11** 할 일은 마감일을 하나 가질 수 있다. 마감일은 날짜만(연·월·일) 가지며 시각과 시간대는 담지 않는다. 할 일을 추가할 때 마감일을 함께 고를 수 있고, 비워 두면 마감일이 없는 할 일로 추가된다. 마감일이 없는 것도 정상 상태이며 오류가 아니다.
- **REQ-12** 마감일은 `YYYY-MM-DD` 형식의 날짜로 주고받으며, 달력에 실제로 있는 날짜만 받는다. 형식이 다르거나(예: `2026-3-1`, `03/01/2026`) 실제로 없는 날짜(예: `2026-02-30`, `2026-13-01`)면 요청을 거절하고 목록과 기존 마감일을 바꾸지 않는다. 윤년의 `2024-02-29`는 허용하고 평년의 `2026-02-29`는 거절한다. 과거 날짜는 거절하지 않고 그대로 받는다.
- **REQ-13** 이미 추가한 할 일의 마감일을 나중에 다른 날짜로 바꿀 수 있고, 지워서 마감일 없는 상태로 되돌릴 수 있다. 마감일이 없던 할 일에 마감일을 새로 넣을 수도 있다. 마감일을 바꾸거나 지워도 그 할 일의 제목과 완료 여부는 그대로 유지되고, 다른 할 일은 영향을 받지 않는다.
- **REQ-14** 목록에서 각 할 일의 마감일을 함께 보여 준다. 마감일이 없는 할 일은 마감일이 없다는 것을 한국어로 알 수 있게 보여 준다. 마감일을 넣거나 바꾸거나 지워도 목록의 순서(REQ-04)는 바뀌지 않는다.
- **REQ-15** (구현 예정 #14) 필터로 거르는 일은 화면에서만 한다. 서버는 필터 조건을 받지 않고 언제나 전체 목록을 추가한 순서대로 돌려주며, 사용자가 필터 선택을 바꿀 때 화면은 서버에 요청을 보내지 않고 이미 받아 둔 목록에서 조건에 맞는 것만 골라 다시 그린다.
- **REQ-16** (구현 예정 #14) 고른 조건에 맞는 할 일이 하나도 없으면 목록 자리에 그 선택에 맞는 한국어 문구 하나를 보여 준다. "전체"일 때는 "할 일이 없습니다.", "진행 중"일 때는 "진행 중인 할 일이 없습니다.", "완료"일 때는 "완료한 할 일이 없습니다."다.
- **REQ-17** (구현 예정 #14) 필터를 바꿔도 할 일의 제목·완료 여부·마감일은 그대로이고, 보이는 할 일들은 추가한 순서(REQ-04)를 그대로 유지한다. 조건에서 벗어난 할 일은 목록에서 보이지 않을 뿐 지워지지 않으며, "전체"를 고르면 다시 모두 보인다. 할 일을 추가하거나, 완료 여부나 마감일을 바꾸거나, 삭제한 뒤에도 고른 필터가 "전체"로 돌아가지 않고 그대로 유지되며, 목록은 그 기준으로 다시 그려진다. 이때 조건에서 벗어난 할 일이 목록에서 사라져 보이는 것은 정상이고, "전체"를 고르면 다시 보인다.

## API 계약

- 모든 API는 `/api/` 아래에 두고 요청과 응답 본문은 JSON(`Content-Type: application/json; charset=utf-8`)을 사용한다.
- 할 일 한 건의 표현: `{"id": 1, "title": "장보기", "done": false, "due": "2026-03-01"}`
  - `id`: 1부터 시작해 추가할 때마다 커지는 정수. 삭제한 ID는 다시 쓰지 않는다.
  - `title`: 앞뒤 공백을 제거한 제목 문자열.
  - `done`: 완료 여부(`true`/`false`).
  - `due`: 마감일. `YYYY-MM-DD` 형식의 문자열이거나, 마감일이 없으면 `null`이다(REQ-11). 응답에서는 마감일이 없어도 이 키를 빼지 않고 항상 `null`로 담는다.
- 오류 응답 본문: `{"error": {"code": "<코드>", "message": "<한국어 안내>"}}`
  - `code`는 아래에 정의한 값만 사용하고, `message`는 그 코드에 정해 둔 한국어 문구를 글자 그대로 담는다.
  - 서버는 정의하지 않은 코드나 문구(내부 오류 문자열, 사용자가 보낸 값, 다른 언어의 문구 등)를 오류 응답에 담지 않는다.

| 메서드 | 경로 | 요청 본문 | 성공 응답 | 오류 |
| --- | --- | --- | --- | --- |
| `GET` | `/` | 없음 | `200` + `index.html` | - |
| `GET` | `/api/todos` | 없음 | `200` + `{"todos": [할 일, ...]}` (추가한 순서, 비어 있으면 `[]`) | - |
| `POST` | `/api/todos` | `{"title": "장보기", "due": "2026-03-01"}` (`due`는 생략 가능, `null`도 허용) | `201` + 추가된 할 일 | `400 invalid_json`, `400 title_blank`, `400 title_too_long`, `400 due_invalid` |
| `PATCH` | `/api/todos/{id}` | `{"done": true}`, `{"due": "2026-03-01"}`, `{"due": null}` 또는 이들을 함께 담은 본문 | `200` + 변경된 할 일 | `400 invalid_json`, `400 done_required`, `400 due_invalid`, `400 nothing_to_update`, `404 not_found` |
| `DELETE` | `/api/todos/{id}` | 없음 | `204`(본문 없음) | `404 not_found` |

- `GET /api/todos`는 필터 조건을 받지 않는다. 질의 문자열(예: `?done=true`, `?filter=active`)을 붙여 보내도 모두 무시하고 언제나 전체 목록을 추가한 순서대로 돌려준다. 거르기는 화면에서만 하므로 필터를 위한 새 경로나 매개변수를 두지 않는다(REQ-15).
- `POST /api/todos`에서 `due`를 생략하거나 `null`로 보내면 마감일 없는 할 일로 추가한다(REQ-11).
- `PATCH /api/todos/{id}`는 본문에 담긴 항목만 바꾼다. `done`만 보내면 마감일은 그대로 두고, `due`만 보내면 완료 여부는 그대로 둔다. `due`에 날짜 문자열을 보내면 그 날짜로 바꾸고, `due`를 `null`로 보내면 마감일을 지운다(REQ-13). `done`과 `due` 둘 다 없으면 `400 nothing_to_update`로 거절하고 아무것도 바꾸지 않는다.
- 오류 코드와 안내 문구
  - `invalid_json`: "요청 형식이 올바르지 않습니다." (JSON이 아니거나 `title`이 문자열이 아닌 등. `due`가 문자열도 `null`도 아닌 경우도 포함한다)
  - `title_blank`: "할 일 제목을 입력해 주세요."
  - `title_too_long`: "할 일 제목은 200자까지 입력할 수 있습니다." (200자는 REQ-03의 셈 방식, 즉 유니코드 문자 수 기준)
  - `done_required`: "완료 여부(done)를 true 또는 false로 보내 주세요." (`done`을 보냈으나 `true`/`false`가 아닌 경우)
  - `due_invalid`: "마감일은 2026-03-01처럼 실제로 있는 날짜로 입력해 주세요." (형식이 `YYYY-MM-DD`가 아니거나 달력에 없는 날짜인 경우, REQ-12)
  - `nothing_to_update`: "바꿀 내용을 보내 주세요. 완료 여부(done) 또는 마감일(due)이 필요합니다."
  - `not_found`: "해당 할 일을 찾을 수 없습니다."
  - `method_not_allowed`: "허용되지 않은 요청 방식입니다."
- 경로의 `{id}`가 정수가 아니면 `404 not_found`로 응답한다.
- 위 표에 없는 경로는 `404 not_found`, 표에 있는 경로에 정의되지 않은 메서드는 `405 method_not_allowed`로 응답한다. 이 두 응답도 위의 오류 응답 본문 형식과 문구를 그대로 따른다.

## 범위 밖

- 로그인, 사용자 계정, 여러 사용자 구분, 권한.
- 데이터베이스와 파일 등 영속 저장. 서버 재시작 후 목록이 비는 것은 정상 동작이다(REQ-09).
- 서버에서 거르기. 리더 결정에 따라 필터는 화면에서만 처리하므로(REQ-15) `GET /api/todos`에 필터 조건을 받는 질의 문자열이나 필터 전용 경로를 두지 않는다. 할 일이 많아져 서버 거르기가 필요해지면 별도 요청으로 다룬다.
- 화면을 새로 열었을 때 이전 필터 선택을 되살리는 것. 새로 고침이나 재방문 후 선택을 되살리거나, 주소(URL)에 선택을 담거나, 브라우저 저장소를 쓰는 일은 이번에 정하지 않는다. 새로 열면 언제나 "전체"로 시작한다(REQ-10). 화면을 열어 둔 동안 추가·변경·삭제를 해도 선택이 유지되는 것은 범위 안이며 REQ-17에서 정한다.
- 필터와 관련해 아직 정하지 않은 것: 선택별 개수 표시("진행 중 3" 등), 두 조건 이상 동시 선택, 마감일이나 제목을 기준으로 거르기, 필터와 정렬·검색을 함께 쓰기.
- 필터를 눌렀을 때 목록이 실제로 걸러져 그려지는지 브라우저로 자동 확인하는 것. REQ-08과 같은 이유로 자동 검사 범위 밖이며, 화면에 들어갈 선택지와 문구가 문서와 같은지까지만 자동으로 확인하고 눌러 본 결과는 구현 PR에서 사람이 확인한다(REQ-10, REQ-16, REQ-17).
- 브라우저를 띄워 화면 동작을 자동으로 확인하는 검사. 테스트는 브라우저 없이 실행하므로, 화면에 보일 오류 문구가 API 계약과 같은지까지만 자동으로 확인하고 실제 표시 동작은 구현 PR에서 사람이 확인한다(REQ-08).
- 이어 붙인 이모지를 한 글자로 묶어 세는 정확한 글자 수 계산. 이번에는 REQ-03의 유니코드 문자 수 기준으로만 세고, 더 정확한 셈이 필요해지면 별도 요청으로 다룬다.
- 마감일이 지난 항목을 눈에 띄게 표시하는 것. 요청에서 제외한 항목이므로 이번에는 정의하지 않고 별도 이슈로 다룬다(REQ-11~REQ-14는 마감일을 저장·수정·표시하는 것까지만 정한다).
- 마감일의 시각·시간대. 마감일은 날짜만 다루며(REQ-11), "오늘"이나 "지났는지"를 판단하는 기준 시간대도 이번에 정하지 않는다.
- 마감일을 기준으로 목록을 정렬하거나 걸러 보는 것. 목록 순서는 추가한 순서 그대로다(REQ-04, REQ-14).
- 마감일 알림, 반복 일정, 마감일 일괄 변경.
- 우선순위 기능. 리더가 마감일을 먼저 진행하기로 결정했으므로 이번 문서에서는 정의하지 않고 나중에 별도 요청으로 다룬다.
- 아직 정하지 않아 이번에 다루지 않는 것: 추가한 할 일의 제목 수정, 여러 건 한 번에 삭제하거나 완료 처리, 완료된 항목 일괄 정리, 정렬 변경, 검색, 목록 페이지 나누기, 되돌리기(삭제 취소), 삭제 전 확인 절차.
- 배포 환경 구성, 모바일 전용 화면, 접근성·디자인 시스템 적용, 다국어 지원.
