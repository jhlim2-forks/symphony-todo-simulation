# 요구사항

## 배경

팀원이 브라우저에서 할 일을 간단히 적고 지울 수 있는 웹앱이 필요합니다(이슈 #4). 첫 버전은 할 일 추가, 추가한 순서대로 목록 보기, 완료 표시와 해제, 개별 삭제까지만 제공합니다.

화면은 한 페이지이고 한국어로 보여 줍니다. 데이터는 서버 메모리에만 두므로 서버를 다시 켜면 목록이 비어 있어도 괜찮습니다. 로그인과 여러 사용자, 데이터베이스는 이번 범위가 아닙니다.

목록을 "진행 중 / 완료"로 나눠 보는 필터는 나중에 만들기로 하고, 이번에는 정의만 남겨 둡니다. 리더 결정에 따라 화면에는 필터가 들어갈 자리만 설계로 정해 두고 동작은 만들지 않습니다.

할 일마다 마감일을 붙이는 동작은 이미 정해 두었고(이슈 #7), 그 정의를 REQ-11~REQ-14로 그대로 유지합니다.

이어서 할 일마다 우선순위(높음 / 보통 / 낮음)를 둘 수 있게 정의합니다(이슈 #8). 기본값은 보통이고, 추가할 때 고를 수 있고 나중에 바꿀 수 있습니다. 목록은 우선순위가 높은 것부터 보여 주고, 같은 우선순위 안에서는 추가한 순서를 지킵니다. 이 때문에 목록 순서 규칙(REQ-04)과 할 일 한 건의 표현, 추가·변경 요청 형식을 함께 고칩니다. 리더 결정에 따라 목록에서 우선순위는 글자만이 아니라 색이 있는 배지 같은 표시로도 한눈에 구분되게 정의합니다. 우선순위는 이미 다른 뜻으로 쓴 ID를 다시 쓰지 않도록 아래 REQ-15~REQ-18로 새로 정의합니다.

## 요구사항

- **REQ-01** (구현 예정 #4) 사용자가 할 일 제목을 입력해 새 할 일을 추가할 수 있다. 추가된 할 일은 고유한 숫자 ID를 가지고, 처음에는 완료되지 않은 상태다.
- **REQ-02** (구현 예정 #4) 제목의 앞뒤 공백은 제거한 뒤 저장한다. 공백을 제거한 제목이 비어 있으면 추가를 거절하고 목록을 바꾸지 않는다.
- **REQ-03** (구현 예정 #4) 공백을 제거한 제목이 200자를 넘으면 추가를 거절하고 목록을 바꾸지 않는다. 200자까지는 허용한다. 글자 수는 바이트 수가 아니라 유니코드 문자(코드 포인트) 수로 세며, 한글 "가", 영문자 "a", 숫자, 이모지 "🙂"처럼 화면에 한 글자로 보이는 문자는 종류와 상관없이 각각 1자로 센다. 따라서 한글 200자 제목은 허용하고 한글 201자 제목은 거절한다. 단, 여러 문자를 이어 붙여 한 글자처럼 보이는 이모지(가족 이모지, 피부색을 붙인 이모지 등)는 이어 붙인 문자 수만큼 센다.
- **REQ-04** (구현 예정 #8) 할 일 목록은 우선순위가 높은 것부터(높음 → 보통 → 낮음) 보여 주고, 같은 우선순위 안에서는 추가한 순서(오래된 것이 위)대로 보여 준다. 완료 표시나 해제는 순서를 바꾸지 않는다.
- **REQ-05** (구현 예정 #4) 목록의 할 일을 완료로 표시할 수 있고, 완료된 할 일을 다시 미완료로 해제할 수 있다. 같은 상태로 다시 바꿔도 오류 없이 그 상태를 유지한다.
- **REQ-06** (구현 예정 #4) 목록의 할 일을 하나씩 삭제할 수 있다. 삭제한 할 일은 목록에서 사라지고 다른 할 일의 순서와 상태는 그대로 유지된다.
- **REQ-07** (구현 예정 #4) 없는 ID로 상태 변경이나 삭제를 요청하면 해당 할 일이 없음을 알리고 목록을 바꾸지 않는다.
- **REQ-08** (구현 예정 #4) 화면은 한 페이지(`index.html`)이고 모든 안내 문구와 오류 메시지를 한국어로 보여 준다. 추가, 완료 표시와 해제, 삭제를 이 한 페이지에서 모두 할 수 있다. 화면에 보여 주는 오류 문구는 API 계약에 정해 둔 한국어 문구이거나, 계약에 없는 응답일 때 쓰는 한국어 기본 문구 "요청을 처리할 수 없습니다. 잠시 후 다시 시도해 주세요."뿐이다. 응답 본문의 다른 내용은 화면에 그대로 보여 주지 않는다.
- **REQ-09** (구현 예정 #4) 할 일은 서버 메모리에만 보관한다. 서버를 다시 시작하면 목록은 빈 상태로 시작한다.
- **REQ-10** (구현 예정) 목록을 "전체 / 진행 중 / 완료"로 나눠 보는 필터를 제공한다. 이번 요청에서는 만들지 않고, 화면에 들어갈 자리만 설계에 정해 둔다.
- **REQ-11** (구현 예정 #7) 할 일은 마감일을 하나 가질 수 있다. 마감일은 날짜만(연·월·일) 가지며 시각과 시간대는 담지 않는다. 할 일을 추가할 때 마감일을 함께 고를 수 있고, 비워 두면 마감일이 없는 할 일로 추가된다. 마감일이 없는 것도 정상 상태이며 오류가 아니다.
- **REQ-12** (구현 예정 #7) 마감일은 `YYYY-MM-DD` 형식의 날짜로 주고받으며, 달력에 실제로 있는 날짜만 받는다. 형식이 다르거나(예: `2026-3-1`, `03/01/2026`) 실제로 없는 날짜(예: `2026-02-30`, `2026-13-01`)면 요청을 거절하고 목록과 기존 마감일을 바꾸지 않는다. 윤년의 `2024-02-29`는 허용하고 평년의 `2026-02-29`는 거절한다. 과거 날짜는 거절하지 않고 그대로 받는다.
- **REQ-13** (구현 예정 #7) 이미 추가한 할 일의 마감일을 나중에 다른 날짜로 바꿀 수 있고, 지워서 마감일 없는 상태로 되돌릴 수 있다. 마감일이 없던 할 일에 마감일을 새로 넣을 수도 있다. 마감일을 바꾸거나 지워도 그 할 일의 제목과 완료 여부, 우선순위는 그대로 유지되고, 다른 할 일은 영향을 받지 않는다.
- **REQ-14** (구현 예정 #7) 목록에서 각 할 일의 마감일을 함께 보여 준다. 마감일이 없는 할 일은 마감일이 없다는 것을 한국어로 알 수 있게 보여 준다. 마감일을 넣거나 바꾸거나 지워도 목록의 순서(REQ-04)는 바뀌지 않는다.
- **REQ-15** (구현 예정 #8) 할 일은 우선순위를 하나씩 가진다. 우선순위는 높음, 보통, 낮음 세 단계뿐이고 다른 값은 없다. 우선순위를 정하지 않고 추가하면 보통이 된다.
- **REQ-16** (구현 예정 #8) 할 일을 추가할 때 화면에서 우선순위를 고를 수 있고, 고르지 않으면 보통으로 추가된다. 세 단계가 아닌 값으로 추가를 요청하면 거절하고 목록을 바꾸지 않는다.
- **REQ-17** (구현 예정 #8) 이미 추가한 할 일의 우선순위를 화면에서 다른 단계로 바꿀 수 있다. 바꾼 뒤 목록은 REQ-04의 순서 규칙에 맞게 다시 정렬되며, 제목·완료 여부·마감일·추가한 순서는 바뀌지 않는다. 같은 단계로 다시 바꿔도 오류 없이 그 단계를 유지하고, 세 단계가 아닌 값으로 바꾸려 하면 거절하고 목록을 바꾸지 않는다.
- **REQ-18** (구현 예정 #8) 목록의 각 할 일은 자기 우선순위를 "높음 / 보통 / 낮음" 한국어 글자와 함께, 단계마다 다른 색을 쓰는 배지 표시로도 보여 준다. 글자만 보거나 색만 보아도 어느 단계인지 알 수 있어야 하므로 배지에는 글자와 색을 함께 담고, 색만으로 구분하게 두지 않는다.

## API 계약

- 모든 API는 `/api/` 아래에 두고 요청과 응답 본문은 JSON(`Content-Type: application/json; charset=utf-8`)을 사용한다.
- 할 일 한 건의 표현: `{"id": 1, "title": "장보기", "done": false, "priority": "normal", "due": null}`
  - `id`: 1부터 시작해 추가할 때마다 커지는 정수. 삭제한 ID는 다시 쓰지 않는다.
  - `title`: 앞뒤 공백을 제거한 제목 문자열.
  - `done`: 완료 여부(`true`/`false`).
  - `priority`: 우선순위. `"high"`(높음), `"normal"`(보통), `"low"`(낮음) 세 값만 쓴다(REQ-15). 응답에는 언제나 이 필드가 들어간다.
  - `due`: 마감일. `YYYY-MM-DD` 형식의 문자열이거나, 마감일이 없으면 `null`이다(REQ-11). 응답에서는 마감일이 없어도 이 키를 빼지 않고 항상 `null`로 담는다.
- 우선순위 값과 화면에 보여 줄 한국어 이름의 짝은 `high`→"높음", `normal`→"보통", `low`→"낮음"이다. 화면은 이 이름만 보여 주고, API 본문에는 영문 값만 담는다.
- 오류 응답 본문: `{"error": {"code": "<코드>", "message": "<한국어 안내>"}}`
  - `code`는 아래에 정의한 값만 사용하고, `message`는 그 코드에 정해 둔 한국어 문구를 글자 그대로 담는다.
  - 서버는 정의하지 않은 코드나 문구(내부 오류 문자열, 사용자가 보낸 값, 다른 언어의 문구 등)를 오류 응답에 담지 않는다.

| 메서드 | 경로 | 요청 본문 | 성공 응답 | 오류 |
| --- | --- | --- | --- | --- |
| `GET` | `/` | 없음 | `200` + `index.html` | - |
| `GET` | `/api/todos` | 없음 | `200` + `{"todos": [할 일, ...]}` (REQ-04의 순서, 비어 있으면 `[]`) | - |
| `POST` | `/api/todos` | `{"title": "장보기", "priority": "high", "due": "2026-03-01"}` (`priority` 생략 가능, 생략하면 `"normal"`. `due`도 생략 가능하고 `null`도 허용) | `201` + 추가된 할 일 | `400 invalid_json`, `400 title_blank`, `400 title_too_long`, `400 invalid_priority`, `400 due_invalid` |
| `PATCH` | `/api/todos/{id}` | `{"done": true}`, `{"priority": "low"}`, `{"due": "2026-03-01"}`, `{"due": null}`, 또는 이들을 함께 담은 본문 (하나 이상 필요) | `200` + 변경된 할 일 | `400 invalid_json`, `400 done_required`, `400 invalid_priority`, `400 due_invalid`, `400 nothing_to_update`, `404 not_found` |
| `DELETE` | `/api/todos/{id}` | 없음 | `204`(본문 없음) | `404 not_found` |

- 오류 코드와 안내 문구
  - `invalid_json`: "요청 형식이 올바르지 않습니다." (JSON이 아니거나 `title`이 문자열이 아닌 등. `due`가 문자열도 `null`도 아닌 경우도 포함한다)
  - `title_blank`: "할 일 제목을 입력해 주세요."
  - `title_too_long`: "할 일 제목은 200자까지 입력할 수 있습니다." (200자는 REQ-03의 셈 방식, 즉 유니코드 문자 수 기준)
  - `done_required`: "완료 여부(done)를 true 또는 false로 보내 주세요." (`done`을 보냈지만 `true`/`false`가 아닐 때)
  - `invalid_priority`: "우선순위는 높음, 보통, 낮음 중에서 골라 주세요." (`priority`를 보냈지만 `high`/`normal`/`low`가 아닐 때. 문자열이 아닌 값이나 `"높음"` 같은 한국어 이름도 이 오류로 거절한다)
  - `due_invalid`: "마감일은 2026-03-01처럼 실제로 있는 날짜로 입력해 주세요." (형식이 `YYYY-MM-DD`가 아니거나 달력에 없는 날짜인 경우, REQ-12)
  - `nothing_to_update`: "바꿀 내용을 보내 주세요. 완료 여부(done), 우선순위(priority), 마감일(due) 중 하나가 필요합니다." (`PATCH` 본문에 `done`, `priority`, `due`가 모두 없을 때)
  - `not_found`: "해당 할 일을 찾을 수 없습니다."
  - `method_not_allowed`: "허용되지 않은 요청 방식입니다."
- `POST /api/todos`에서 `due`를 생략하거나 `null`로 보내면 마감일 없는 할 일로 추가한다(REQ-11).
- `PATCH`는 `done`, `priority`, `due` 중 보낸 값만 바꾼다. `done`만 보내면 우선순위와 마감일은 그대로 두고, `priority`만 보내면 완료 여부와 마감일은 그대로 둔다(REQ-17). `due`에 날짜 문자열을 보내면 그 날짜로 바꾸고 `due: null`은 마감일을 지운다(REQ-13). 여러 값을 함께 보내면 모두 검증한 뒤 적용하며, 오류일 때는 아무 값도 바꾸지 않는다.
- 경로의 `{id}`가 정수가 아니면 `404 not_found`로 응답한다.
- 위 표에 없는 경로는 `404 not_found`, 표에 있는 경로에 정의되지 않은 메서드는 `405 method_not_allowed`로 응답한다. 이 두 응답도 위의 오류 응답 본문 형식과 문구를 그대로 따른다.

## 범위 밖

- 로그인, 사용자 계정, 여러 사용자 구분, 권한.
- 데이터베이스와 파일 등 영속 저장. 서버 재시작 후 목록이 비는 것은 정상 동작이다(REQ-09).
- "진행 중 / 완료" 필터의 동작 구현. 이번에는 정의와 화면 자리만 두고 나중에 별도 이슈로 만든다(REQ-10).
- 브라우저를 띄워 화면 동작을 자동으로 확인하는 검사. 테스트는 브라우저 없이 실행하므로, 화면이 서버에서 받는 HTML에서 확인할 수 있는 것(필요한 요소가 있는지, 문구·우선순위 이름·배지 클래스가 계약과 같은지, 같은 값을 다른 곳에 다시 적지 않았는지)까지만 자동으로 확인한다. 고른 우선순위가 실제로 전송되는지, 배지가 각 줄에 그려지는지, 변경 뒤 목록이 다시 그려지는지처럼 브라우저가 스크립트를 실행해야 알 수 있는 동작은 구현 PR에서 사람이 확인한다(REQ-08, REQ-14, REQ-16, REQ-17, REQ-18).
- 이어 붙인 이모지를 한 글자로 묶어 세는 정확한 글자 수 계산. 이번에는 REQ-03의 유니코드 문자 수 기준으로만 세고, 더 정확한 셈이 필요해지면 별도 요청으로 다룬다.
- 마감일이 지난 항목을 눈에 띄게 표시하는 것. 요청에서 제외한 항목이므로 이번에는 정의하지 않고 별도 이슈로 다룬다(REQ-11~REQ-14는 마감일을 저장·수정·표시하는 것까지만 정한다).
- 마감일의 시각·시간대. 마감일은 날짜만 다루며(REQ-11), "오늘"이나 "지났는지"를 판단하는 기준 시간대도 정하지 않는다.
- 마감일을 기준으로 목록을 정렬하거나 걸러 보는 것. 목록 순서는 REQ-04의 우선순위 순서와 추가한 순서로만 정한다(REQ-04, REQ-14).
- 마감일 알림, 반복 일정, 마감일 일괄 변경.
- 우선순위에서 이번에 다루지 않는 것(이슈 #8의 요청에 없어 정하지 않음): 우선순위로 목록을 걸러 보기, 사용자가 정렬 기준이나 방향을 직접 바꾸기, 끌어다 놓아 순서를 손으로 바꾸기, 여러 건의 우선순위를 한 번에 바꾸기, 우선순위를 바꾼 이력 보기, 세 단계를 늘리거나 이름·색을 사용자가 고치기.
- 배지에 쓸 정확한 색 값과 디자인 세부는 설계에서 한 벌만 정하고, 색 선택 기준과 테마·대비 비율 같은 디자인 시스템 수준의 결정은 다루지 않는다(REQ-18).
- 아직 정하지 않아 이번에 다루지 않는 것: 추가한 할 일의 제목 수정, 여러 건 한 번에 삭제하거나 완료 처리, 완료된 항목 일괄 정리, 검색, 목록 페이지 나누기, 되돌리기(삭제 취소), 삭제 전 확인 절차.
- 배포 환경 구성, 모바일 전용 화면, 접근성·디자인 시스템 적용, 다국어 지원.
