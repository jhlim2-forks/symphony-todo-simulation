# 요구사항

## 배경

팀원이 브라우저에서 할 일을 간단히 적고 지울 수 있는 웹앱이 필요합니다(이슈 #4). 첫 요청에서는 할 일 추가, 추가한 순서대로 목록 보기, 완료 표시와 해제, 개별 삭제까지를 정했고, 이후 요청에서 마감일(이슈 #7), 필터(이슈 #14), 완료 항목 일괄 삭제(이슈 #16), 기한 지남 표시(이슈 #9)를 더했습니다.

화면은 한 페이지이고 한국어로 보여 줍니다. 데이터는 서버 메모리에만 두므로 서버를 다시 켜면 목록이 비어 있어도 괜찮습니다. 로그인과 여러 사용자, 데이터베이스는 이번 범위가 아닙니다.

목록을 나눠 보는 필터는 이 문서가 정하는 동작에 포함됩니다. 첫 요청에서는 화면에 들어갈 자리만 정했으나, 이슈 #14에서 동작과 확인 기준을 정했고 화면과 확인 테스트까지 올라가 구현이 끝났습니다. 화면에는 "전체 / 진행 중 / 완료"를 제공합니다. 구현이 끝났으므로 REQ-10에는 구현 예정 표시를 두지 않습니다.

이어서 완료한 할 일을 한 번에 지우는 동작을 정의합니다(이슈 #16). 완료한 항목이 쌓이면 한 건씩 지우기 번거롭다는 요청이어서, 목록에서 완료된 항목만 한 번에 지우는 버튼을 둡니다. 누르면 바로 지우지 않고 지워질 개수를 보여 주는 확인 창을 거치며, 진행 중인 항목은 지우지 않습니다. 지운 항목을 되살리는 기능은 요청에서 필요 없다고 했으므로 만들지 않습니다. 리더가 이 작업의 위험도를 "높음"으로 유지하고 삭제 전에 지워질 개수를 보여 주는 확인 창을 반드시 넣도록 결정했으므로, 확인 창과 개수 안내를 요구사항으로 못 박아 둡니다.

이어서 할 일마다 마감일을 붙이는 동작을 정의합니다(이슈 #7). 마감일은 날짜만 쓰고 시각과 시간대는 다루지 않습니다. 추가할 때 고르거나 비워 둘 수 있고, 나중에 바꾸거나 지울 수 있으며, 목록에 보이고, 실제로 없는 날짜(예: 2026-02-30)는 거절합니다. 마감일이 지난 항목을 눈에 띄게 하는 일은 그 요청에서 제외되어 별도 이슈(이슈 #9)로 넘겼고, 아래 단락에서 정의합니다. 우선순위 기능과 어느 것을 먼저 할지에 대해서는 리더가 마감일을 먼저 진행하기로 결정했으므로, 마감일 요청에서는 마감일만 정의하고 우선순위는 범위 밖에 남겨 두었습니다.

이어서 마감일이 지난 할 일을 목록에서 눈에 띄게 하는 동작을 정의합니다(이슈 #9). 마감일 기능(REQ-11~REQ-14)이 먼저 들어가야 하는 일이어서 미뤄 두었으나 이제 정의합니다. 마감일이 오늘보다 앞서고 아직 완료하지 않은 할 일만 "기한 지남"으로 보고, 오늘 마감인 항목과 완료한 항목은 강조하지 않습니다. "오늘"은 서버가 실행되는 환경의 지역 날짜를 기준으로 하며, 마감일에 시각과 시간대를 더하는 일은 여전히 하지 않습니다. 리더가 "기한 지남" 표시를 색상뿐 아니라 글자로도 보이게 해 달라고 조건을 달았으므로, 빨간 글씨와 "기한 지남" 문구를 함께 쓰도록 요구사항에 못 박아 둡니다. 기한 지남 여부는 서버가 응답할 때마다 계산해 알려 주는 값이고 사용자가 정하는 값이 아니므로, 리더 결정에 따라 요청 본문에 이 값이 들어와도 거절하지 않고 모르는 항목처럼 무시합니다. 동작 정의는 이 문서로 확정하되 코드는 아직 없으므로, 구현 전 상태는 REQ-19~REQ-22에 붙인 `(구현 예정 #9)` 표시로 나타내고 확인 테스트를 함께 올리는 구현 단계에서 이 표시를 지웁니다.

## 요구사항

- **REQ-01** 사용자가 할 일 제목을 입력해 새 할 일을 추가할 수 있다. 추가된 할 일은 고유한 숫자 ID를 가지고, 처음에는 완료되지 않은 상태다.
- **REQ-02** 제목의 앞뒤 공백은 제거한 뒤 저장한다. 공백을 제거한 제목이 비어 있으면 추가를 거절하고 목록을 바꾸지 않는다.
- **REQ-03** 공백을 제거한 제목이 200자를 넘으면 추가를 거절하고 목록을 바꾸지 않는다. 200자까지는 허용한다. 글자 수는 바이트 수가 아니라 유니코드 문자(코드 포인트) 수로 세며, 한글 "가", 영문자 "a", 숫자, 이모지 "🙂"처럼 화면에 한 글자로 보이는 문자는 종류와 상관없이 각각 1자로 센다. 따라서 한글 200자 제목은 허용하고 한글 201자 제목은 거절한다. 단, 여러 문자를 이어 붙여 한 글자처럼 보이는 이모지(가족 이모지, 피부색을 붙인 이모지 등)는 이어 붙인 문자 수만큼 센다.
- **REQ-04** 할 일 목록은 추가한 순서(오래된 것이 위)대로 보여 준다. 완료 표시나 해제는 순서를 바꾸지 않는다.
- **REQ-05** 목록의 할 일을 완료로 표시할 수 있고, 완료된 할 일을 다시 미완료로 해제할 수 있다. 같은 상태로 다시 바꿔도 오류 없이 그 상태를 유지한다.
- **REQ-06** 목록의 할 일을 하나씩 삭제할 수 있다. 삭제한 할 일은 목록에서 사라지고 다른 할 일의 순서와 상태는 그대로 유지된다.
- **REQ-07** 없는 ID로 상태 변경이나 삭제를 요청하면 해당 할 일이 없음을 알리고 목록을 바꾸지 않는다.
- **REQ-08** 화면은 한 페이지(`index.html`)이고 모든 안내 문구와 오류 메시지를 한국어로 보여 준다. 추가, 완료 표시와 해제, 삭제를 이 한 페이지에서 모두 할 수 있다. 화면에 보여 주는 오류 문구는 API 계약에 정해 둔 한국어 문구이거나, 계약에 없는 응답일 때 쓰는 한국어 기본 문구 "요청을 처리할 수 없습니다. 잠시 후 다시 시도해 주세요."뿐이다. 응답 본문의 다른 내용은 화면에 그대로 보여 주지 않는다.
- **REQ-09** 할 일은 서버 메모리에만 보관한다. 서버를 다시 시작하면 목록은 빈 상태로 시작한다.
- **REQ-10** 목록을 "전체 / 진행 중 / 완료"로 나눠 보는 필터를 화면에 제공한다. 선택지는 이 세 가지뿐이고 한 번에 하나만 고를 수 있다. 처음에는 "전체"가 선택된다. "전체"는 모든 할 일, "진행 중"은 완료되지 않은 할 일(`done`이 `false`), "완료"는 완료된 할 일(`done`이 `true`)만 목록에 보여 준다. 거르기는 화면에서만 하며 서버는 전체 목록을 반환한다. 조건에 맞는 항목이 없으면 각각 "할 일이 없습니다.", "진행 중인 할 일이 없습니다.", "완료한 할 일이 없습니다."를 보여 준다. 필터를 바꾸는 것은 목록에 무엇을 보여 줄지만 바꾼다. 각 할 일의 제목·완료 여부·마감일은 그대로이고, 보이는 항목들의 순서도 추가한 순서(REQ-04)를 그대로 따른다. 고른 조건에서 벗어난 할 일은 지워진 것이 아니라 가려진 것이며, 다시 "전체"를 고르면 필터를 쓰기 전과 같은 항목이 같은 순서로 보인다. 서버에 보관된 목록도 필터 때문에 바뀌지 않는다. 할 일을 추가하거나 삭제한 뒤에도 선택한 필터를 유지한다. 완료 여부나 마감일 변경 뒤 선택 상태는 이번에 정하지 않는다.
- **REQ-11** 할 일은 마감일을 하나 가질 수 있다. 마감일은 날짜만(연·월·일) 가지며 시각과 시간대는 담지 않는다. 할 일을 추가할 때 마감일을 함께 고를 수 있고, 비워 두면 마감일이 없는 할 일로 추가된다. 마감일이 없는 것도 정상 상태이며 오류가 아니다.
- **REQ-12** 마감일은 `YYYY-MM-DD` 형식의 날짜로 주고받으며, 달력에 실제로 있는 날짜만 받는다. 형식이 다르거나(예: `2026-3-1`, `03/01/2026`) 실제로 없는 날짜(예: `2026-02-30`, `2026-13-01`)면 요청을 거절하고 목록과 기존 마감일을 바꾸지 않는다. 윤년의 `2024-02-29`는 허용하고 평년의 `2026-02-29`는 거절한다. 과거 날짜는 거절하지 않고 그대로 받는다.
- **REQ-13** 이미 추가한 할 일의 마감일을 나중에 다른 날짜로 바꿀 수 있고, 지워서 마감일 없는 상태로 되돌릴 수 있다. 마감일이 없던 할 일에 마감일을 새로 넣을 수도 있다. 마감일을 바꾸거나 지워도 그 할 일의 제목과 완료 여부는 그대로 유지되고, 다른 할 일은 영향을 받지 않는다.
- **REQ-14** 목록에서 각 할 일의 마감일을 함께 보여 준다. 마감일이 없는 할 일은 마감일이 없다는 것을 한국어로 알 수 있게 보여 준다. 마감일을 넣거나 바꾸거나 지워도 목록의 순서(REQ-04)는 바뀌지 않는다.
- **REQ-15** 완료한 할 일을 한 번에 지우는 버튼을 화면에 하나 둔다. 완료된 할 일이 하나도 없으면 이 버튼을 누를 수 없는 상태로 두어, 지울 것이 없을 때는 아무 동작도 일어나지 않는다.
- **REQ-16** 이 버튼을 누르면 바로 지우지 않고, 지워질 완료 항목의 개수를 한국어로 보여 주는 확인 창을 먼저 띄운다. 사용자가 확인하면 지우고, 취소하면 서버에 아무 요청도 보내지 않고 목록을 그대로 둔다.
- **REQ-17** 일괄 삭제는 완료된 할 일만 지운다. 진행 중(미완료)인 할 일은 한 건도 지우지 않으며, 남은 할 일의 추가 순서와 제목·완료 여부·마감일은 그대로 유지된다. 지운 할 일의 ID는 다시 쓰지 않는다.
- **REQ-18** 일괄 삭제는 되돌릴 수 없다. 지운 항목을 되살리는 기능은 제공하지 않는다. 서버는 이번에 지운 개수와 남은 목록을 응답으로 알려 주고, 화면은 그 결과로 목록을 다시 그려 서버 상태와 일치시킨다. 지울 완료 항목이 하나도 없는 상태에서 요청이 들어와도 오류로 보지 않고 지운 개수 0으로 응답하며 목록을 바꾸지 않는다.
- **REQ-19** (구현 예정 #9) 마감일이 오늘보다 앞서고 완료되지 않은 할 일만 기한 지남으로 판정한다. 오늘 마감, 완료, 마감일 없는 할 일은 기한 지남이 아니다.
- **REQ-20** (구현 예정 #9) 오늘은 서버가 실행되는 환경의 지역 날짜이며 판정은 요청 처리 때 계산한다.
- **REQ-21** (구현 예정 #9) 할 일을 반환하는 모든 응답은 서버가 계산한 `overdue`를 항상 포함한다. 요청 본문에 `overdue`가 오면 다른 모르는 항목과 같이 무시하고 저장하지 않는다. `PATCH`에 `overdue`만 있으면 `nothing_to_update`다.
- **REQ-22** (구현 예정 #9) 기한 지남인 할 일은 빨간 글씨와 "기한 지남" 문구를 함께 표시한다. 다른 할 일은 강조하지 않고 목록 순서와 내용은 바꾸지 않는다.

## API 계약

- 모든 API는 `/api/` 아래에 두고 요청과 응답 본문은 JSON(`Content-Type: application/json; charset=utf-8`)을 사용한다.
- 할 일 한 건의 표현: `{"id": 1, "title": "장보기", "done": false, "due": "2026-03-01", "overdue": false}`
  - `id`: 1부터 시작해 추가할 때마다 커지는 정수. 삭제한 ID는 다시 쓰지 않는다.
  - `title`: 앞뒤 공백을 제거한 제목 문자열.
  - `done`: 완료 여부(`true`/`false`).
  - `overdue`: 서버가 요청 시점에 계산하는 기한 지남 여부이며 응답에 항상 포함한다(REQ-21).
  - `due`: 마감일. `YYYY-MM-DD` 형식의 문자열이거나, 마감일이 없으면 `null`이다(REQ-11). 응답에서는 마감일이 없어도 이 키를 빼지 않고 항상 `null`로 담는다.
- 오류 응답 본문: `{"error": {"code": "<코드>", "message": "<한국어 안내>"}}`
  - `code`는 아래에 정의한 값만 사용하고, `message`는 그 코드에 정해 둔 한국어 문구를 글자 그대로 담는다.
  - 서버는 정의하지 않은 코드나 문구(내부 오류 문자열, 사용자가 보낸 값, 다른 언어의 문구 등)를 오류 응답에 담지 않는다.

| 메서드 | 경로 | 요청 본문 | 성공 응답 | 오류 |
| --- | --- | --- | --- | --- |
| `GET` | `/` | 없음 | `200` + `index.html` | - |
| `GET` | `/api/todos` | 없음 | `200` + `{"todos": [할 일, ...]}` (추가한 순서, 비어 있으면 `[]`) | - |
| `POST` | `/api/todos` | `{"title": "장보기", "due": "2026-03-01"}` (`due`는 생략 가능, `null`도 허용) | `201` + 추가된 할 일 | `400 invalid_json`, `400 title_blank`, `400 title_too_long`, `400 due_invalid` |
| `PATCH` | `/api/todos/{id}` | `{"done": true}`, `{"due": "2026-03-01"}`, `{"due": null}` 또는 이들을 함께 담은 본문 | `200` + 변경된 할 일 | `400 invalid_json`, `400 done_required`, `400 due_invalid`, `400 nothing_to_update`, `404 not_found` |
| `DELETE` | `/api/todos/completed` | 없음 | `200` + `{"deleted": 2, "todos": [남은 할 일, ...]}` | - |
| `DELETE` | `/api/todos/{id}` | 없음 | `204`(본문 없음) | `404 not_found` |

- `DELETE /api/todos/completed`는 완료된(`done: true`) 할 일을 모두 지운다(REQ-15, REQ-17). 응답의 `deleted`는 이번 요청으로 지운 개수(0 이상의 정수)이고, `todos`는 삭제 후 남은 전체 목록을 추가한 순서대로 담는다(남은 것이 없으면 `[]`). 지울 완료 항목이 없으면 `deleted`가 `0`이고 목록은 그대로이며, 이때도 오류가 아니라 `200`이다(REQ-18).
- 경로 `/api/todos/completed`는 `/api/todos/{id}`보다 먼저 맞춰 본다. 즉 `completed`는 할 일 ID가 아닌 고정된 경로이며, `GET`·`POST`·`PATCH`처럼 이 경로에 정의되지 않은 메서드는 `405 method_not_allowed`로 응답한다.
- `overdue`는 서버 계산값이다. 요청에 포함되어도 무시하며 거절하지 않는다. `PATCH`에 `overdue`만 있으면 `400 nothing_to_update`다(REQ-21).
- `POST /api/todos`에서 `due`를 생략하거나 `null`로 보내면 마감일 없는 할 일로 추가한다(REQ-11).
- `PATCH /api/todos/{id}`는 본문에 담긴 항목만 바꾼다. `done`만 보내면 마감일은 그대로 두고, `due`만 보내면 완료 여부는 그대로 둔다. `due`에 날짜 문자열을 보내면 그 날짜로 바꾸고, `due`를 `null`로 보내면 마감일을 지운다(REQ-13). `done`과 `due` 둘 다 없으면 `400 nothing_to_update`로 거절하고 아무것도 바꾸지 않는다.
- 오류 코드와 안내 문구
  - `invalid_json`: "요청 형식이 올바르지 않습니다." (JSON이 아니거나 `title`이 문자열이 아닌 등. `due`가 문자열도 `null`도 아닌 경우도 포함한다)
  - `title_blank`: "할 일 제목을 입력해 주세요."
  - `title_too_long`: "할 일 제목은 200자까지 입력할 수 있습니다." (200자는 REQ-03의 셈 방식, 즉 유니코드 문자 수 기준)
  - `done_required`: "완료 여부(done)를 true 또는 false로 보내 주세요." (`done`을 보냈으나 `true`/`false`가 아닌 경우)
  - `due_invalid`: "마감일은 2026-03-01처럼 실제로 있는 날짜로 입력해 주세요." (형식이 `YYYY-MM-DD`가 아니거나 달력에 없는 날짜인 경우, REQ-12)
  - `nothing_to_update`: "바꿀 내용을 보내 주세요. 완료 여부(done) 또는 마감일(due)이 필요합니다."
  - `not_found`: "해당 할 일을 찾을 수 없습니다."
  - `method_not_allowed`: "허용되지 않은 요청 방식입니다."
- 경로의 `{id}`가 정수가 아니면 `404 not_found`로 응답한다.
- 위 표에 없는 경로는 `404 not_found`, 표에 있는 경로에 정의되지 않은 메서드는 `405 method_not_allowed`로 응답한다. 이 두 응답도 위의 오류 응답 본문 형식과 문구를 그대로 따른다.

## 범위 밖

- 로그인, 사용자 계정, 여러 사용자 구분, 권한.
- 데이터베이스와 파일 등 영속 저장. 서버 재시작 후 목록이 비는 것은 정상 동작이다(REQ-09).
- 화면을 새로 열었을 때 이전 필터 선택을 되살리는 것. 다시 열면 "전체"로 시작한다(REQ-10).
- 완료 여부나 마감일 변경 뒤 필터 선택 상태. 이번에 정하지 않는다(REQ-10).
- 필터 선택별 개수, 여러 조건 동시 선택, 마감일·제목 기준 필터링, 필터와 정렬·검색 결합.
- 브라우저를 띄워 화면 동작을 자동으로 확인하는 검사. 테스트는 브라우저 없이 실행하므로, 화면에 보일 오류 문구가 API 계약과 같은지까지만 자동으로 확인하고 실제 표시 동작은 구현 PR에서 사람이 확인한다(REQ-08).
- 이어 붙인 이모지를 한 글자로 묶어 세는 정확한 글자 수 계산. 이번에는 REQ-03의 유니코드 문자 수 기준으로만 세고, 더 정확한 셈이 필요해지면 별도 요청으로 다룬다.
- (범위 밖에서 빠짐) 마감일이 지난 항목을 눈에 띄게 표시하는 것은 더 이상 범위 밖이 아니다. 마감일 요청(REQ-11~REQ-14)에서 미뤄 두었던 이 동작을 이슈 #9에서 REQ-19~REQ-22로 정했고, 아직 코드가 없어 구현 예정 상태일 뿐이다.
- 기한이 지난 지 며칠 되었는지 세어 보여 주는 것, 기한 지남 항목만 걸러 보거나 위로 모아 보여 주는 것. 강조는 REQ-22의 빨간 글씨와 "기한 지남" 문구까지만 한다.
- 마감일의 시각·시간대. 마감일은 날짜만 다루며(REQ-11), "오늘"은 서버가 실행되는 환경의 지역 날짜로만 판단한다(REQ-20). 사용자가 보는 곳의 시간대나 시간대를 고르는 설정은 이번에 다루지 않는다.
- 마감일을 기준으로 목록을 정렬하거나 걸러 보는 것. 목록 순서는 추가한 순서 그대로다(REQ-04, REQ-14).
- 마감일 알림, 반복 일정, 마감일 일괄 변경.
- 우선순위 기능. 리더가 마감일을 먼저 진행하기로 결정했으므로 이번 문서에서는 정의하지 않고 나중에 별도 요청으로 다룬다.
- 지운 항목을 되살리는 기능(되돌리기, 휴지통, 삭제 기록 보관). 요청에서 "되살릴 수 없어도 괜찮다"고 했으므로 이번에 만들지 않는다(REQ-18).
- 진행 중인 항목을 포함해 여러 건을 골라서 한 번에 지우는 것. 이번 일괄 삭제는 완료된 항목만 대상으로 한다(REQ-17). 체크박스로 지울 항목을 직접 고르는 방식도 이번 범위가 아니다.
- 여러 건을 한 번에 완료로 바꾸거나 해제하는 것.
- 한 건씩 지우는 삭제(REQ-06)에 확인 창을 붙이는 것. 확인 창은 이번에 추가하는 일괄 삭제에만 둔다(REQ-16).
- 일괄 삭제가 끝난 뒤 "N개를 지웠습니다" 같은 성공 안내를 화면에 보여 주는 것. 화면 문구는 REQ-08에 정해 둔 오류 문구 체계만 쓰기로 했으므로 이번에는 정하지 않고, 필요해지면 별도 요청으로 다룬다. 서버가 돌려주는 `deleted` 개수는 화면이 목록을 다시 그리는 데만 쓴다.
- 확인 창의 생김새(직접 만든 모달, 디자인, 버튼 배치). 브라우저가 제공하는 확인 창을 쓰기로 정했고(설계 참고), 꾸미는 일은 이번 범위가 아니다.
- 아직 정하지 않아 이번에 다루지 않는 것: 추가한 할 일의 제목 수정, 정렬 변경, 검색, 목록 페이지 나누기.
- 배포 환경 구성, 모바일 전용 화면, 접근성·디자인 시스템 적용, 다국어 지원.
